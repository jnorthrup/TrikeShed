## 2024-06-25 - Use zero-allocation `j` constructor instead of intermediate List allocations for `Series`
**Learning:** In tight rendering loops (like `ExtrudedSceneProjection`), chaining operations like `.drop(1).map { ... }` and combining lists using `+` to eventually call `.toSeries()` allocates multiple intermediate `ArrayList` instances, negatively impacting performance. This can be heavily optimized using the `j` Series constructor.
**Action:** When creating a `Series` from an indexable collection where each element has a well-defined projection (like `p: List<Vec3>` mapped to `PathPart.Line`), use the size-based `j` constructor (e.g. `p.size j { i: Int -> if (i == 0) PathPart.Move(p[0]) else PathPart.Line(p[i]) }`). To avoid ambiguous resolution to the overloaded `Tuple2` constructor (which also uses `j`), explicitly type the lambda argument as `Int` and parenthesize any math in the size expression. This creates a lazy `MappedSeries` and prevents all intermediate allocations.
