## 2026-09-23 - Map allocation bypass for sorted Teleported objects
**Learning:** In Kotlin, mapping a collection with `associate { ... }` creates a temporary `Map` (often a `LinkedHashMap`). If this intermediate `Map` is immediately consumed by `.toList().sortedBy { ... }.toMap()`, it incurs the allocation cost of the map, its entries, and the subsequent list. Mapping directly to `Pair` instances using `.map { ... }` bypasses the temporary map allocation.
**Action:** When mapping standard collections or properties like `Map.entries` that implement `Iterable`, avoid chaining `.associate { ... }.toList().sortedBy { ... }.toMap()`. Instead, map directly to `Pair`s using `.map { ... }.sortedBy { ... }.toMap()` to prevent unnecessary intermediate `Map` and `List` allocations.
