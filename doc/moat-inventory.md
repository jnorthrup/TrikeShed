# Moat inventory — the incomplete concepts

Inert record, 2026-09-06, HEAD 0f99c47b1. Nothing here dispatches: there are no checkboxes, and
`doc/todo.md` stays the only live intake. Each row is what the tree holds today, re-verified by grep
when written (callers, tests, daemon references), not what a doc says it holds. States:

| State | Meaning |
|---|---|
| complete-and-wired | code, tests, and a daemon/UI/CLI/lego caller; the concept does its job today |
| partial | wired, but a named piece of the concept's own definition is missing |
| works-but-orphaned | code and tests exist; no product caller reaches it |
| spec-only | a doc defines it; no implementing code |
| dead | code exists with no caller and a superseding path, or a doc describes a deleted thing |

The moat is the set of concepts no competitor has to build to ship a workflow tool, and which the
post that started Forge ([forge-genesis.md](forge-genesis.md)) does not ask for by name: content
addressing under everything, one reactor vocabulary, one blackboard, a production system as the
judge, Couch-shaped replication, btrfs semantics in userspace, a patch algebra for merging, a
sub-VM that reports pointcuts as facts. Incomplete is the honest state of most of it.
