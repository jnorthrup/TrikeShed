R3e working mechanics — verification and publication pending

Wire projection is synchronous browser presentation over the existing page owner. redrawWires now takes one geometry snapshot: it reads each distinct node/direction/bare-port endpoint once, including absent endpoints, then reads viewport width and height. A local cache lives only for that redraw. It is not a persistent scene cache and cannot authorize geometry across a later edit, camera change or async boundary. Endpoints are materialized before new SVG paths are attached, because leaving their computation lazy would interleave later reads with writes again.

The existing curve/clipping algorithm receives measured width and height explicitly. Its original viewport overload remains for temporary drag wires and other callers. Paths, mismatch/refusal titles, typed labels and existing page-owned pointer handlers are built on a document fragment and attached together. Wire-box growth still uses actual endpoints and reprojects through the existing camera. No new executor, scheduler, time budget, owner or event stream is introduced. This does not remove quadratic node overlap work or repeated graph serialization, and it does not establish large-graph capacity.

The verification driver measures trusted keyboard input on the existing Resume/Pause display button after the actual receipt body arrives. The application button receives real CDP key events; its handler is not replaced. Chromium's Event Timing entries describe quantized event-to-next-paint duration and processing timestamps when reported; the minimum threshold is 16 ms. Missing entries cannot be treated as zero latency. A separately recorded handler-to-requestAnimationFrame interval is not paint latency. Node protocol round-trip time includes controller/protocol overhead and is not physical-input latency. The baseline and candidate must use the same driver, fresh processes and an idle build host.

After the timing window, the driver fits the graph, zooms around the measured shared-source port and resizes the viewport. Every path whose two endpoints are visible must match the actual port centers within one screen pixel. Pairs clipped by the viewport are counted separately. The first two harness pilots incorrectly demanded an eligible endpoint pair after zooming around the centre of the viewport, which moved the shared source offscreen. No product change was made to satisfy that invalid assumption. The third pilot passes against immutable R3d and records 64, 27 and 17 eligible pairs across its three views. Those pilot timings overlap Gradle work and have no performance acceptance standing. A real pointer click deletes one exposed wire, preserves the 65 nodes and invalidates the old trace without submitting another run.

D3M retains the new source-pinned corpus query replay evidence, native Horn proof-quad inspection and static-note readiness fix. Initial integration required correcting missing collection brackets in production/test code and viewing a filtered Series at the stdlib association boundary. Failed compiler logs and the original branch IDs remain. Query behavior and coverage assertions were not removed.

The now-runnable Horn tests exposed a separate common collection defect. Reify returns LinearArrayMap, whose anonymous entries inherited object identity hashing. AbstractMap's structural equality could therefore compare a reified nested row equal to an ordinary map while deriving a different hash from those entries. Recreating the entries could change that hash again. Exact query rows were refused when used in hash-based row coverage and ordering. An in-process Java diagnostic against the compiled fixture and actual SPARQL engine reproduced equal maps and a failed HashMap lookup. LinearArrayMap entries now implement the Map.Entry equality/hash contract. NativeHornQueryView retains its exact typed-row membership, duplicate/missing-row refusal, context identity and ordering checks. The regression covers nested row keys in both lookup directions, null values, field-order changes and lookup beyond the map's small linear threshold.

Native Horn proof quads are a request-local projection of supplied checked proof/selection context. Fixed inspection programs query actual variable bindings or ordered premise uses through the existing quad engine. A data row does not establish native execution, source entailment, authenticated review or a sink permit. The complete projection has bounded source context and typed provenance. Existing external solver tests may remain conditional; final results must report their actual skips and distinguish them from authored certificate/projection fixtures. Incoming replay evidence keeps its own tested identities.
