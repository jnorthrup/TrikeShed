ml-nix / TrikeShed / SUMO: articulated KIF activation review
2026-11-02, bounded read-only source audit. No production source edits, dependency installation, builds or new test executions. Public upstream files inspected read-only through GitHub connector.

Recommendation
Make scoped KIF formulas and explicit activation/proof dependencies authoritative, with a SUMO semantic extension and an optional physical set index underneath. Do not globally remove Roaring first. A dependency hierarchy can explain what must be reconsidered when assertions change; it does not by itself prove entailment, implement quantifiers, or replace NAL evidence policy. The dependency structure must allow DAGs, multiple supports and cycles, not just a single-parent tree.

What ml-nix actually means in the inspected tree
build.gradle.kts:195-240 names an optional sibling `../mlir-nix` (override -PmlirNix.dir), include/mlnix-c/MlnixC.h and build/lib/libmlnix-c.dylib. It conditionally adds macOS cinterop and src/mlirMain. src/mlirMain/kotlin/borg/trikeshed/mlir/MlirMain.kt invokes mlnixOpen, mlnixRoundTrip, mlnixError, mlnixFree, mlnixClose to parse/verify/print a module. src/macosMain/resources/META-INF/cinterop/mlnixC.def declares that C header.
The public upstream https://github.com/jnorthrup/mlir-nix was inspected at commit 7edfaba88ce1d6a615d211b0e9d757c7cb7e83bb. It implements a Nix-compatible evaluator, store and CLI on MLIR. README describes Nix2.35.4/Lix2.91.3 comparison, mlnix/nix-instantiate/nix-build/nix-store behavior, demand evaluation and TrikeShed algebra. Upstream benchmark/test counts are upstream reports, not rerun evidence here. License LGPL2.1.

Thus the actual project supplies lazy frames, demand nodes, external models, recursive expression structure and reproducible store dependencies. It does not currently establish logical activation/retraction/proof rules; recursive SSA is not a least-fixed-point solver, and store DAG cycle rejection cannot implement arbitrary cyclic ontology reasoning.
src/commonMain/kotlin/borg/trikeshed/mlir/MlirCore.kt is a Kotlin catalog of standard MLIR dialect/op names and string type signatures, not a registered generic KIF or SUMO dialect. userspace/tensor/Mlir.kt contains explicit placeholder coordination/builders; it is not evidence of a working logical lowering pipeline. No actual KIF/SUMO TableGen/C++ MLIR dialect was found.

Existing logical representations and real limits
src/commonMain/kotlin/borg/trikeshed/kif/Kif.kt has KifExpr.Atom, Var, ListExpr and Quoted; strict parseAll rejects truncated strings/lists and stray closing parentheses. It preserves nested syntactic expressions, but forall/exists/connectives remain ordinary list heads. There is no scoped binder identity, formula-vs-term typing or quantifier evaluator. The single-expression parse entry is permissive and does not enforce complete consumption. Its query implementation performs structural unification against assertions plus subclass transitive closure; its broad comment about conjunction/instance must not be read as implemented full FOL semantics. Variables are name strings, not alpha-safe lexical references.
The same file's subclassSnapshot exposes revisioned direct edges, names and closure IDs. That is a useful existing explainability seam, but closure membership lacks a per-answer proof derivation. Revisions guard stale cache reinstall after mutation. New semantic compilation should enter via strict parsing and preserve the exact original form/source reference, not replace the assertion store with lowered fragments.
src/commonMain/kotlin/borg/trikeshed/ontology/SumoClassifier.kt explicitly projects only top-level atomic subclass, instance, domain/range and disjoint/decomposition declarations. It counts rules and unprojected taxonomy rather than flattening quantified/functional forms into edges. SumoOntology.kt is a small manually sourced upper spine, not the complete ontology. Corpus pins: utils/sumo/{sumo-corpus,sumo-full-corpus}.pins, ontologyportal/sumo revision25bb366fdffd8769e741d2e22f215c2785bddce1, checksummed files; the full selection is78files, not an upstream-defined release. Preserve source licensing/pins and distinguish upper spine vs pinned corpus.

Where Roaring is used, and why a blanket replacement is wrong
src/commonMain/kotlin/borg/trikeshed/collections/bits/RoaringSeries.kt is a local immutable Roaring-shaped integer set (array/bitmap/run containers), not simply a dependency on an external RoaringBitmap package. ClosureIndex in that directory gives DFS-numbered taxonomy reachability; SumoClassifier uses its ancestor/descendant sets, instance masks and disjoint masks. Raw class preorder IDs are classifier-local and must never become cross-version logical identities.
src/commonMain/kotlin/borg/trikeshed/narsese/ClassRete.kt indexes eternal antecedent/consequent columns, intersects class ancestry with antecedent IDs, then offers discounted/floored NAL support. It is an efficient restricted matching/evidence seam, not arbitrary quantified KIF reasoning.
src/commonMain/kotlin/borg/trikeshed/narsese/Constellation.kt uses sets for book/section provenance, statement support, SUMO bearer matches and premise joins. Its Fired result already distinguishes pending, blocked and conflicted. An unless condition requires explicit negative evidence; absence is not negation. EvidenceLedger.kt and Inheritance.kt also use Roaring for source basis and overlap protection. Replacing those support sets with an activation tree would lose shared-support identity and risk double counting unless their semantics are explicitly preserved. No distinct fully articulated SUMO frame activation engine was established by this audit.

NARS and operational Rete boundary
src/commonMain/kotlin/borg/trikeshed/narsese/CausalityRete.kt admits restricted atemporal implication/equivalence and emits potential discounted support; bag admission remains separate. EternalRule.fromKif accepts atom-shaped positional forms, not a general binder/connective compiler. Do not route generic formulas through that helper as if logically lossless.
src/commonMain/kotlin/borg/trikeshed/dag/ReteProduction.kt declares interests and operational activations; its rule evaluator does not itself mutate working memory. KifTee.kt mirrors ASSERT/MODIFY/RETRACT into exact bank projections, retaining fact identity and using atomic bank.replace. It must not recurse into Rete while holding the observer/write lock. These are reusable update/ownership seams, not a logical truth-maintenance proof system. NAL graded evidence, deterministic logical derivation, agenda scheduling and host effects need separate explicit result kinds.

Proposed architecture (design, not existing APIs)
1. Generic KIF semantic IR above indexes: distinct Term and Formula categories; constants/literals/functions, free variables and lexically scoped bound references; application, quote, forall, exists, not, and, or, implies and equivalence; opaque modality/context forms retained until a declared semantics exists. Preserve arity, nested terms, binder scope, source CID/span, original syntax and admission status. Alpha-renaming may normalize identities but must never capture variables. Unrecognized SUO-KIF/row-variable/higher-order forms remain represented and explicitly unsupported for execution.
2. Generic KIF MLIR dialect should encode those categories with verified regions/block arguments for binders and typed formula results, rather than prematurely lowering every proposition to i1. Logical truth is open-world and may have conflicting evidence; execution returns entailment/refutation/unknown/conflict (or explicit support sets), separate from bool control flow. Quote and modality cannot be erased. Generic KIF describes expressions; SUMO adds ontology vocabulary/axiom constraints and corpus identity. A SUMO dialect extension can reference/embed generic KIF formulas and add subclass/instance/domain/range declarations with provenance, then lower only a declared supported fragment. It is not a replacement parser for all KIF, and SUMO is ontology semantics rather than merely an MLIR spelling.
3. Activation-plan layer: stable source-backed assertion/rule identities, dependency edges from premises and substitutions to candidate conclusions, multiple justification nodes, rule-version/policy identifiers and explicit invalidation. distinguish scheduled, matched, logically derived, refuted, pending, conflicting and unsupported. Memoized plan evaluation can align with upstream Node/Frame and external-interface models; its current C ABI cannot execute them. Immutable revision/frame replacement is the initial safe invalidation policy; mutable reactivation would require new reverse-dependency and support tracking. A proposed Nix-style reactivation layer would recompute affected plans on changed inputs; current call-by-need memoization alone does not implement this, nor establish a rule's logical validity. Cycles need SCC/worklist/fixpoint policy and termination/budget limits, not recursive eager evaluation.
4. Runtime hooks: immutable assertion revision snapshot in; typed delta assert/retract/replace and targeted invalidation; pure rule evaluation; proof/source receipts out; host-owned effect admission after logical results. Retraction removes a conclusion only after its last valid support disappears. Ground candidates can be accelerated by sorted sets, Roaring or other indexes behind a backend interface. An index hit is a candidate/membership result, never the whole proof. Avoid global backend abstraction churn until one real semantic consumer exists.

Smallest feasible first slice
Implement a scoped read-only KIF formula decoder/verifier plus a source-backed activation/explanation plan for the existing positive ground subclass/instance fragment. Keep the existing classifier/query backend and pinned corpus unchanged. Explain a small diamond inheritance path with multiple independent supports and revisioned invalidation; allow an optional reference adjacency traversal and existing Roaring-backed path to yield identical answers/support sets. Preserve other formula kinds in IR but return explicit unsupported-execution status; do not silently drop them or claim full SUMO reasoning. Pin the inspected mlir-nix revision and add genuine KIF/SUMO registered dialects and explicit evaluator/bridge entry points before claiming native execution. Reuse its external-model pattern while preserving KIF-specific proof/result types. Next, implement a genuine generic KIF dialect with parser/verifier roundtrip tests and a SUMO extension/lowering for exactly that fragment, not mere Kotlin op-name strings.

Meaningful acceptance tests (proposed; none run here)
- Strict complete parse/print; nested forall/exists with shadowed names, alpha-equivalence, free-variable preservation, quoted strings/formulas and function terms. Not/and/or/implies/equivalence/modality survive roundtrip unchanged in meaning.
- Unknown fact is not false; explicit negative and simultaneous positive/negative are distinguishable; unsupported quantified rules do not manufacture ground edges.
- Diamond and cyclic subclass graphs, class-vs-instance distinction, disjointness and domain/range semantics; exact stable term identity across reindexed snapshots.
- Two sources support one conclusion; retract one preserves it, retract last removes it; assert/modify/retract invalidates only affected plans, stale revision cannot reinstall an old result. Proof receipts recover exact source/rule versions and substitutions.
- Differential adjacency-vs-Roaring results and support sets on synthetic graphs plus pinned taxonomy; separately benchmark memory/time without treating performance as correctness.
- NAL evidence overlap/deduplication and discount behavior unchanged; operational Rete agenda effects require host admission; no callbacks across prohibited lock ownership.
