# Programme charter and invariants

## Product outcome

An operator loads a complex retained agreement or PDF and a question set. The screen shows source passages, branching review work, engine activity and proposed outputs. Activity remains legible when engines produce thousands of events per second. The operator can zoom from the whole factory into one premise, pause execution at a meaningful boundary, inspect why a branch exists, replace an algorithm or narrow a filter, and continue with preserved lineage.

The same machinery must support legal analysis, evidence mapping, fictional world continuity, transcript memories, personal or borrowed histories, IPFS collections and news analysis. Domain differences live in source policies, question schemas, rules, review criteria and output templates. A legal dispute and a fictional continuity dispute may share mechanics without sharing authority or truth conditions.

The long-term outcome is a recurrent production system: slow analysis discovers useful patterns, NARS-like memory allocates attention and represents revisable empirical expectations, and a constrained compiler proposes Rete productions. Stable work becomes cheaper. New evidence or changed assumptions deoptimizes that work and sends it back to analysis. Myelinization means a guarded optimization with a visible revocation path.

## Scope of the first demonstrator

The initial demonstration has three domain packs. The legal pack uses a retained Coinbase agreement capture, a small evidence dossier, and explicit hypothetical questions. The symbolic pack uses synthetic ground facts and Horn rules with known answers. The fiction/news pack demonstrates that different contexts and sources remain separate while sharing the same graph, clocks, memory and publication mechanics.

The initial factory contains several sources, parallel middle lanes, one nested reasoning scope and at least two sinks. A second run changes the width of a panel and the depth of a question tree. A third run changes source evidence and visibly invalidates a previously usable production. A replay reproduces the recorded decisions without re-running external effects.

The application must show live measured execution, paced presentation of recorded execution, and synthetic simulation as distinct modes. A synthetic scheduler fixture is useful for renderer stress and demonstrations of behaviour unavailable in an engine. It cannot stand in for actual parser, solver or production integration evidence.

## Invariants

| ID | Invariant | Consequence |
|---|---|---|
| I01 | Original source bytes are immutable | Denaturing and extraction create new artifacts with transformations and anchors |
| I02 | Source identity and source authority differ | A matching hash proves retained bytes, not author authenticity or legal force |
| I03 | Every semantic object has an explicit context | Hypothetical, fictional, asserted and derived data cannot leak through a default union |
| I04 | Review has a named object and scope | Approval of an extraction does not approve its truth or its production use |
| I05 | Absence, opposition and contradiction differ | Missing evidence cannot become a negative premise |
| I06 | Retrieval and attention do not add evidence | Repeated recall and duplicate proof paths cannot inflate confidence |
| I07 | A proof identifies its admitted fragment and inputs | Unsupported KIF remains visible; a timeout is not an unknown logical answer |
| I08 | Semantic events and effects are durable or refused | A green UI pulse cannot precede the completion it claims |
| I09 | Presentation clocks do not drive execution | Slow motion affects viewing unless a separate execution control is issued |
| I10 | Outstanding work has an owner and terminal accounting | Pause, shutdown and restart expose in-flight effects and incomplete attempts |
| I11 | Configuration changes produce a new version | Old evidence remains historical and cannot silently certify the new graph |
| I12 | Production authority is separate from confidence | A high-scoring hypothesis is not an executable permission |
| I13 | Every production has revocation dependencies | Changed source, policy, mapping or runtime can return it to analysis |
| I14 | Airgap is a deployment property with evidence | A UI model-egress flag alone does not establish host-wide isolation |
| I15 | CPU and model costs are measured separately | Optional ML must earn its resource use against a non-ML reference |

## Meaning of the central terms

**LCNC** is the user-facing construction grammar for sources, transformations, scoped analyses, controls and outputs. It includes type and capability constraints, defaults, explanations and bounded composition. It is more than drag-and-drop layout.

**Curation** retains source identity, anchors observations, records selections and assessments, and exposes those records through RDF and wiki projections. It does not make a document correct merely by storing it.

**Engine** is an algorithm or runtime with a declared input fragment, output semantics, resource contract and observation support. A regex matcher, SAT solver, NARS bag and language model are all engines, but their result types differ.

**Panel** is a set of roles or procedures coordinated over a question frame. Roles may be deterministic analyses, human reviewers or model-assisted agents. A judge role applies a configured decision procedure and produces a simulation result; it does not claim judicial authority.

**Production** is a versioned condition/action artifact with permitted effects, exact dependencies and deployment status. A display sink, a candidate rule and an active production are different objects.

**Human view** is a bounded projection of execution: stable spatial organization, rates, queues, timers, summarized transitions and drilldown. It is the ladle for the event stream. It must reveal what was summarized and how to recover the underlying records.

## Cardinality and scale requirements

Sources may be singular documents, ordered collections or streams. Middle scopes may run zero, one or many branches. Outputs may be absent because work is unresolved, or plural because alternatives remain valid. A diagram with three source cards and three panel seats is one configuration, not a limit.

Bounded breadth and depth are required independently. A branch limit is a work budget, not a statement that other outcomes are impossible. The UI displays generated, admitted, completed, excluded and deferred branches. For recursive work, the retained frontier is part of the result.

The programme uses a small real-data fixture for causal correctness and larger synthetic fixtures for load. Success at 10,000 visual nodes does not establish that 10,000 concurrent inference processes are feasible. Success at one clause does not establish legal coverage of an entire agreement.

## Delivery levels

**D0 — contract and fixture:** the graph definition, event schema, artifact identities, retained scenarios and expected outcomes agree. The UI can replay a clearly labeled reference trace.

**D1 — instrumented vertical slice:** real document retention, an exact source anchor, a deterministic middle operation and a retained result appear in one live trace. A pause acknowledgement identifies its boundary.

**D2 — integrated demonstrator:** multiple source types, nested panels, optional local parsing, a positive Horn proof, evidence drilldown, rescaffolding, production shadowing and revocation are connected. All scripted demonstrations pass under blocked egress.

**D3 — offline release candidate:** recovery and repeatability, installation without network, long-running bounded resources, packaging, documentation and sustained UI performance are demonstrated on named hardware.

**D4 — research platform:** broader inference fragments, validated local model selection, larger corpora, adaptive production economics and general domain packs evolve through experiments with explicit stopping criteria.

## Boundaries that require decisions during implementation

The first production effects are local and reversible: cache population, routing to an existing bounded analysis, and publication into a versioned local derived graph. Real external publication, transfers and account actions need their own existing authorization policies and are outside the demonstrator's automatic effects.

Use explicitly fictional or synthetic assumptions when demonstrating a legal outcome branch. Actual agreement captures and court opinions supply source-reading material. Do not fill factual gaps by silently constructing a customer history. Retain separate dates for the agreement version, events, court decision and analysis cutoff.

The user requested documents and implementation planning. This package therefore specifies future work and its acceptance evidence; it does not change production code, install models, run a legal verdict or launch an unattended paid development programme.
