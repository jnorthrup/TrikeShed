## Invariant ownership

Source/evidence packages own I01–I07. Journal, control and visualization own I08–I11. NARS/production packages own I06 and I12–I13. Offline packaging owns I14. Performance and campaign accounting own I15. WP25 verifies the composed path across all owners; no package can declare an invariant satisfied solely because its own output contains the expected field name.

## Completion accounting

Each package reports implemented, verified, experimental or blocked per capability. A delivery level is achieved only when its required acceptance evidence exists. Optional local models can remain unavailable at D2; source lineage, truthful visualization, pause/fork, proof scope and production revocation cannot.

The document package is complete when its links resolve, its estimates reconcile, each user requirement has a concrete mechanism and owner, and claims distinguish current code from proposals. This does not imply that implementation is complete. Jim's local all-branch D3M merge is complete only after local branch inventory, preserved conflicts, intent repair, verification and a confirmed pushed master; a cloud documentation push does not satisfy that separate action.
