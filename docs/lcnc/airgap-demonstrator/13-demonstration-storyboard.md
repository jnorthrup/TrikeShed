# Demonstration storyboard and fixtures

## Demonstration promise

In approximately twenty minutes, an operator can see a complex source, follow several questions through actual CPU work, inspect an unresolved branch, zoom into a proof, pause and change the scaffold, then observe a reusable production become invalid and return to analysis. The recording must distinguish measured live behaviour from replay and synthetic load.

The source corpus is larger than the selected analysis slice. The demonstration retains the whole agreement/PDF for navigation while explicitly showing selected coverage. The symbolic fixture provides known answers independent of legal interpretation. The domain-switch fixture shows generality without requiring a second runtime.

The blueprints specify these fixtures; their real capture, annotation and executable traces are implementation deliverables. Do not present illustrative IDs or expected events in this package as retained runtime evidence.

## Act one source and scope 0 to 3 minutes

Open the factory overview with no activity until the operator admits a run. The top bar shows source bundle, definition, epoch, offline profile and live mode. Open F01 on the left. Scroll through headings, a table and cross-references. Select a clause and show original capture, safe view and exact quotation identity. A coverage badge says which sections are selected.

Add the F03 question graph and an evidence dossier. The wizard previews branch count, engine availability and resource limits. Show that optional model lanes are unavailable or disabled without preventing the deterministic run. Start the run; actual admissions create the first activity.

Expected visible proof: source identity and selected revision match; no external requests occur; no source becomes reviewed merely by import.

## Act two flow at human speed 3 to 6 minutes

Watch transfers enter lexical filtering, structural inspection and panel scopes. Queue wait and active time are separate. A slow parser has an elapsed timer without a made-up percentage. Hover a scope, then pin its flyover: received passages, active role, unresolved condition and source frame.

Switch from live to follow-with-delay and show the visible lag. The engines continue at their budgeted speed. Return to live. Open a burst on one wire: its band represents a counted group of transfers. Select the group to inspect the retained interval and constituent semantic events.

Expected visible proof: sparks have event references; counts agree with host accounting; presentation pace does not change engine throughput.

## Act three uncertainty and proof 6 to 10 minutes

Open F05. With two assessments complete and withdrawal unknown, the branch remains pending. Add an explicitly hypothetical non-withdrawal premise in a new scenario; eligibility changes locally. Add conflicting support in another branch and show conflict. The host action remains a separate authority check.

Run F04 through the real positive Horn engine. The theory contains `Employee(Alice)`, a class propagation rule, `assignedTo(Alice,ProjectA)`, `authorizedFor(Alice,ProjectA)` and a conjunction rule for `eligibleFor`. Exact syntax follows the supported relational representation. The target tuple is absent from input and derived through the rule.

Zoom into the proof, then into a source premise. Show engine/fragment, frame identity, proof coverage and the distinction between a proof receipt and NAL evidence. Swap one role argument or remove authorization; the supported result disappears in a fresh frame without becoming an assertion that eligibility is false.

Expected visible proof: the engine actually executes, the conclusion is not merely retrieved, and all proof leaves resolve to the admitted source receipts.

## Act four pause and rescaffold 10 to 14 minutes

While another bounded analysis is active, request pause. The UI immediately shows request accepted, then outstanding work and the eventual checkpoint. If a worker only supports process-boundary restart, show that capability honestly.

Fork the graph. Reduce panel seats from five to three, depth from four to two and candidate workset from 64 to 32. The wizard shows which completed artifacts can be reused, which work will repeat and which branches become deferred. Resume under a new epoch. Compare the parent and child runs on coverage, time and unresolved frontier.

Expected visible proof: source and semantic changes create a new definition/frame; old outputs remain historical; a smaller budget reduces coverage explicitly rather than manufacturing equivalent completeness.

## Act five myelinization and deoptimization 14 to 17 minutes

Select a repeated exact question/frame. Propose the local result-reuse or bounded-routing production. Show its guard, dependency set, reference result and measured cost. Run in shadow, inspect agreement with the reference and then activate under the fixture's preconfigured local-effect policy.

Repeat the question. The rightmost production emits an activation and retained local effect receipt, while the expensive middle work is reduced. Show measured saved work. Withdraw one supporting source or review. The generation is suspended; a queued stale activation cannot dispatch. The next query returns to analysis and produces a new scoped result.

Expected visible proof: activation is fenced by generation/currentness, source withdrawal changes current eligibility, and repeated reuse does not increase empirical confidence.

## Act six alternate domain and replay 17 to 20 minutes

Load F06 or F07 through the same graph shell. Show different role procedures and context rules, retaining the same timers, sparks, source links and pause controls. Open F08's missing block as an availability failure with no network fallback.

Replay the earlier run at one-tenth speed, seek to its pause marker, inspect its proof and compare the production's active/suspended states. No engine or effect runs during replay. Switch to the F09 synthetic load fixture to show overview aggregation and zoom responsiveness; keep the synthetic badge visible.

Expected visible proof: domain context isolation, replay without effects, and bounded visualization under load.

## Detailed symbolic fixture

Use explicit positive relational facts and range-restricted rules with stable source IDs. Add a diamond class hierarchy, a cycle, duplicate source records for one assertion, an unrelated project and 1,000 irrelevant near-lexical facts. The selector cap is initially 64 premises and 32 rules with a bounded reverse-dependency traversal, following the existing next-experiment proposal.

Compare full admitted theory, structured preselection and flat top-16 recall. Measure premise recall, selected work, answer status, proof/source equality and engine cost. Record whether selection is complete for the declared fixture. Reordering rules may change a first-proof witness while leaving the supported answer unchanged; the UI must not call this a semantic contradiction.

## Fault choreography

Inject one controlled failure at a time: unavailable parser, malformed source span, stale source revision, solver deadline, duplicate event delivery, subscriber gap, full visual buffer, review withdrawal and process crash after output retention. Each has a predefined expected UI and retained receipt. Reset from a fresh fixture bundle between independent demonstrations so earlier state does not accidentally satisfy later cases.

Do not hide a failure by switching silently to a prerecorded trace. If live execution fails, show the failure and explicitly choose replay to illustrate the intended path. The final acceptance recording contains at least one uninterrupted real source-to-result run and one real production invalidation.

## Deliverable evidence packet

Retain the exact build and bundle manifest, hardware profile, source/fixture identities, program definitions, semantic journal, engine receipts, screenshots or recording, egress evidence, resource measurements and acceptance report. Keep private source material outside public Git and publish content-free summaries where necessary. A reviewer must be able to distinguish fixture expectations from actual observed results without reading the development chat.
