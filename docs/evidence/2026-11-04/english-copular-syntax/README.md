# Fresh English source to visual copular syntax — v68

This is a source and representation pilot using one public synthetic text, one fresh local CoreNLP 4.6 SYNTAX inspection, and one explicit visual query. It demonstrates source-linked syntax observations. It does not establish comprehension, a class assertion, positive legal force, guard scope, or parser accuracy on a corpus.

The native Documents drop stored the exact 228 UTF-8 bytes, including CRLF. The explicit inspection preserved original case, sentence/token spans and qualifications. The production preset gallery then offered an inert eight-pattern copular diagram and a connected outer query. The outer graph ran against the fresh receipt in **current** mode through the existing English query owner and actual Kanban durable run service. No model provider was configured.

## Source and result

The source is [source.txt](source.txt). It contains a prohibited disclosure with an exception, a coordinated copular sentence, and:

> Tenant may occupy unless rent is not due, and only if the permit remains valid.

The query joins recorded `cop` and `nsubj` edges with the same full parser governor ID. Its five columns contain node identities and word labels, not complete sentences. Full quotations, source spans and markers are inspected in Documents and retained in the parent receipt.

| Syntax rows | Subject node | Predicate word | Meaning of the observation |
| --- | --- | --- | --- |
| requirements / clear | `2:0` and `2:3` | clear | Two parser vertices refer to one source occurrence of “requirements”. |
| rent / due | `5:0` | due | The copular syntax also occurs inside the negated, qualified sentence above. It is not a positive obligation or applicability result. |

The source has 42 original tokens and 43 full parser nodes, including one parser copy. The result has three rows. No instance, subclass, approved interpretation, SUMO classification, NARS belief or legal world fact is created.

## Preserved stages and limits

There was one actual parser read and one authored query run across three functional stages, **not one uninterrupted browser attempt**. Attempt 1 performed the native drop and actual inspection, then a stale harness selector targeted a previous gallery layout. Attempt 2 used the actual current gallery and completed the query; automatic evidence opening was invalidated by an asynchronous canvas change. Later read-only Evidence captures typed the existing durable receipt CID without another upload, inspection or query run. The automatic drawer opening has a confirmed UI lifecycle defect: invalidated workspace/receipt callbacks can leave a stale “Reading workspace” state. The successful explicit read-only capture does not establish that this race is fixed; that repair and its response-hold controls belong to the subsequent UI slice. A collector-only retry excluded computed, unsaved workspace program hashes from the set of promised retained run blocks. The original attempts and errors are retained; they are not reported as first-pass successes.

Continuation used production `ProjectScopes.remountLedger` over the same closed CAS and durable project heads. Before serving each continuation, the actual common verifier checked the canonical inspection and original source bytes, and every retained source snapshot exactly matched `corpus.document`. This is a reduced fixture assembly using production owners; it is not a full daemon restart test. The fresh receipt is distinct from the earlier recorded fixture receipt used by unit controls.

The fixture and its in-process Graal parser inherited a seccomp filter denying `connect`, `sendto`, `sendmsg` and `sendmmsg`. Actual socket probes reported permission denied, and `/proc` observed seccomp mode 2 and no-new-privileges during the fresh parse. The parser JVM used `-Xmx4g`. Chromium was outside that process filter and made no external requests. This proves that bounded outbound-denial scope, not a general operating-system sandbox or production-wide air gap.

The runtime emitted an interpreter fallback warning: JDK 25.0.4's compiler version did not match polyglot 25.3.4.1. Version checks were left enabled. This limits performance claims; no substitute parser output was supplied.

Receipts remain `unreviewed`; producer/semantic authority is not established and downstream reads do not re-authenticate parser execution. The bounded invocation ledger reports `inputsOmitted: work_limit` for the inner syntax document. Input identity and mode are checked against the retained authored program and actual query source output; omitted inputs are not represented as complete observations.
