Reviewed source → taxonomy activation consumer: feasibility gate
2026-11-02. Read-only source inspection; no code/build/authority changes.

Decision: do not wire an implicit approved bridge yet. Two real contracts are missing.
1. CurationReview.consume(releaseCid) is the existing authoritative material access, but it appends a consume event and spends a one-shot permit. It is not a read-only query capability. inspect(snapshotCid) returns ledger inspection/current state, not a typed, immutable, reusable reviewed-material capability for a new sink. SourceScopedQuery consumes and then uses a private bag; no production LCNC/HTTP caller of that object was found. Tests named SourceScopedBookIntegrationTest demonstrate the pilot; no separate SourceScopedBookQuery production class was found in the inspected source.
2. Reviewed book/document relationships are source-derived subject/predicate/object/modality/polarity plus exact quotations. They do not declare that their lexical action predicate is KIF subclass or instance. CorpusOntology mappings classify bearer/object terms and explicitly state causalProof=false; selecting that ontology does not review every retained KIF axiom or prove that a verb means taxonomy. A source that says owns/pays/is must not silently become subclass/instance. Current retained ontology KIF is CAS integrity-checked, not automatically approved as a reviewed taxonomy assertion corpus.

Actual authoritative seams
- CurationReview.kt consume at330-344 validates known release/head/current source+ontology, strict condition assessment and approval lineage, then material() resolves selected values from the authoritative candidate and appends admissionCid. Default strict policy applies to books; do not assume all document selections have equivalent strict-book assessment semantics.
- DocumentReviewWire.open installs resolver: book→ConstellationNodes.reviewCandidate, document→DocumentReviewCandidate.candidate. Its current callback checks retained book receipt/source state or document revision/tool ontology and ProjectCorpus currentness plus evidence head/tombstone where applicable. HTTP principal comes from configured Bearer token hash; JSON reviewer/synthetic cannot provide identity.
- ConstellationNodes.reviewCandidate uses BookCurationReceipt.candidateVerified, not submitted selection maps. VerifiedBook verifies frozen receipt/proposal identities, ontology ID and quotation anchors against retained text with bounded CAS reads; this establishes internal source consistency, not authenticity/OCR/legal truth. reviewCurrent checks candidate matches verified receipt and current source/receipt files.
- BookCurationReceipt relationship values include original source quotation, parser action/modality/condition, ontologyMapping/objectMapping and reviewStatus=unreviewed. Reviewed material() adds lineage outside these values; do not use value.reviewStatus or raw SPARQL strings as authority.
- SourceScopedQuery.kt consumes only a STRICT_BOOK unconditional reviewed subset, verifies exact text digest/span and source identity, returns exact proposition/occurrence/selection/snapshot/release/admission/ontology IDs and rechecks current ledger after private-bag work. Its graph field is an exact label, not verified RDF graph membership. It supports at most64selected rows and may lose matches through its private bag. It cannot supply all premises of a multi-hop taxonomy path by repeated calls with the same one-shot release, and its bag residency is irrelevant to the first read-only plan report.

Small coherent implementation proposal (requires explicit root policy choice)
A. Add a separate host-only CurationReview read operation, e.g. reviewedRead(snapshotCid, expectedRevision), serialized by the review actor. Re-resolve/validate exact candidate, current source/ontology, issued approval lineage and strict unconditional assessments; freeze typed selected values+quotation+reviewer/synthetic+approval/snapshot/revision/asOf record. This is non-consuming and returns no admissionCid or reusable sink permit; reject invalidated/corrected/stale/unassessed/conditional material. Root must decide which authentic ledger head states (approve/release/consume) are eligible for this read; do not assume inspection current=true alone is permission. Recheck before returning result, honestly as-of rather than atomic with later changes. Keep consume unchanged for mutating sinks.
B. Bind a real LCNC node or POST /api/documents/review/taxonomy-plan in DocumentReviewWire using that exact host review service/CAS instance. Input only snapshot ID, expected revision and bounded positive-ground goal. Never allow caller-provided review enum, source maps, mapping callback or fabricated approval metadata. If a new read operation is not approved, an alternative explicitly named one-shot consuming report may use consume, but must advertise the ledger mutation and cannot be called read-only.
C. First relation mapping is exact declared predicates subclass or instance only, positive polarity, explicitly supported assertive modality, unconditional assessment and two exact validated KIF constants. Do not map arbitrary parser verbs, case-fold/guess SUMO names, infer from term alignment, or include taxonomy KIF from ontology merely because referenced. Selected unsupported rows stay visible with reason and whole-report coverage limits; if opposition/condition interpretation is unsupported, report unsupported subset rather than invent a full verdict. A fixture must include actual reviewed exact taxonomy rows; current legal prose may yield zero eligible rows, and that is a truthful useful report.
D. Construct KifSourceAssertion only within trusted adapter from this read capability. IDs bind selection+source/quotation+approval identity; sourceCid is actual retained exact text CID; sourceRevision and snapshot revision are host-derived. Keep a sidecar per assertion of original/text CIDs, begin/end/quote, selection/proposition/occurrence identities, approval/snapshot/ontology/reviewer/synthetic and mapping-policy version. Use KifTaxonomySnapshot then activationPlan, retain frame/query/proof/source IDs/export digest and current-positive-fragment semantics. Original/extracted source authentication is not asserted.
E. Report counters: selected rows, eligible taxonomy assertions, excluded rows/reasons, bytes read, proof search steps/proofs/truncation, source/current check timestamp, coverage=current-reviewed-selected-subset-only. Full opposing/unsupported selections remain countable. No global bank/quad mutation; no live bag Mint/Reinforce/Attend; confidence unchanged. The bag remains4096active by current daemon configuration, not5000.

Meaningful acceptance proof before advertising consumer
Real review ledger+verified source fixture (not an approval-map callback): create source/ontology/receipt, authenticated assessment+approval, request read report and show ledger revision unchanged. Exact two-edge/diamond taxonomy goal yields source-backed path with recovered quoted source bytes/receipt mapping; raw verb row and unreviewed/conditional/negative row are not promoted. Repeated read same revision stable frame and no permit spent; actual consume still one-shot. Forged/stale/corrected snapshot, changed source/ontology, missing CAS bytes, row overflow and bounded proof search fail honestly. Raw SPARQL approved marker cannot choose reviewed sources. Assert global NARS evidence/budget/facts unchanged, and no new approved enum constructed from caller input. Expose endpoint/node in production registry with readiness when the host reviewed-read capability is available; no unused generic adapter.

Stop point
No safe reusable reviewed-read capability or declared reviewed taxonomy relation mapping exists yet in the traced production path. Implementing the above requires a deliberate host authority/read-policy addition and authentic taxonomy review fixture, not merely connecting KifActivationPlan to arbitrary quad query rows. Await root decision before coding.
