Bounded native review-observation query — 2026-11-02

POST /api/documents/review/horn-query is an authenticated, non-consuming read
with the same snapshotCid/expectedRevision/goal fields as /horn-input. Only
containsMandatorySelection and needsMapping are accepted. Neither endpoint
asserts world facts, grants a sink permit or spends a review release.
/horn-input remains NOT_EXECUTED preparation. /horn-query defaults to
UNAVAILABLE because DocumentReviewWire.open has no native capability unless
trusted bootstrap code supplies NativeHornQuery(NativeHornProfile(...)).
NativeHornProfile.parse(text) is a pure strict16KiB operator-JSON factory.
Its exact required fields are binary, binarySha256, adapter, datalogDirectory;
optional timeoutMillis is integral1..45000. Relative paths, duplicate/unknown
fields and environment/argv/code fields refuse. It reads no ambient environment.
OroborosLcncWiring.documentReview uses host FileOperations to load the optional
TRIKESHED_NATIVE_HORN_PROFILE absolute operator JSON path, bounded to16KiB.
Unset leaves /horn-query UNAVAILABLE. An invalid explicit profile fails startup.
HTTP cannot select this profile. JSON accepts no environment/code/argv fields.

canonical run.nix and datalog directory, curated process environment and a
wall limit up to45 seconds. The adapter SHA256 is fixed to

An operator must provision and trust the executable's shared libraries/runtime

The host generates reviewed observation JSON, caps actual encoded input at4MiB,
checks inputCID, and writes it in a host-created temporary directory. All
filesystem I/O uses the explicitly installed FileOperations capability and
fileIoContext; missing capability refuses. Profiles contain only normalized
absolute path values until FileOperations canonical resolution during execution.
Before reads, open/size/close rejects oversized trusted files (binary256MiB,
adapter16KiB, datalog1MiB, input4MiB); a required BoundedFileReader enforces
the limit while reading even if the path grows after the size check. Pre/post
hashes and canonical path equality are checked. These checks do not make the
filesystem immutable during execution; operator-owned immutable SDK/profile
paths remain required.
It directly invokes the fixed native instantiate CLI with --argstr path values;
and a fixed --store dummy://, preventing ambient/remote store selection.
There is no POSIX shell, request expression interpolation, client-selected path,
command, profile, timeout or import. Actual pinned mlnix --argstr support was
verified. Executable/adapter/datalog hashes and input bytes are checked before
and after execution; profile filesystem immutability remains an operator duty.

Existing ProcessCaptureChannel and JvmProcessProtocolPipes own the finite CLI.
A new opt-in failOnOverflow policy revokes and joins on the first output above
the cap; existing callers retain head-and-drain behavior by default. Native
queries cap merged stdout+stderr at1MiB. Diagnostics contaminating JSON cause
refusal. Wall timeout and caller cancellation revoke and join the child and
pipe stages. The platform also revokes observed descendants; this is not a
sandbox/process-group containment claim. Existing wire admission drains its
accepted requests on retirement; client disconnect does not discard an accepted
request, which still has the finite host deadline.

Only exit0, untruncated strict JSON with matching schema/frame/input/query/pins
and a checked proof certificate can be returned. The private certificate checker
parses each ground fact with KifSemantic, binds asserted witnesses to that exact
input fact, requires the returned root to equal the query, resolves derived
rule IDs to the exact input rule and associated sources, and verifies ordered
premises and head under one shared variable substitution. It visits only the
supplied certificate (depth64/nodes4096), without theorem search or a Kotlin
replacement solver. Wrong-source/goal/rule/shared-variable certificates refuse.

Reviewed KIF taxonomy — 2026-11-03

POST /api/documents/review/taxonomy-query is a separate authenticated,
non-consuming native query over an exact currently approved KIF snapshot. It
does not accept caller-supplied assertions, proof rules or approval metadata.
The fixed host policy adds subclass transitivity, instance inheritance and
known-class reflexivity rules; those rules are host-defined, not separately
approved source assertions. The result includes the rules and an occurrence
sidecar binding each reviewed source quotation to its approval and read ID.
The existing certificate checker verifies each returned proof against this
exact input. The source and approval are checked before and after execution;
the read grants no release or sink permit. Book modalities never enter this
path. A successful no-proof result means UNKNOWN for this positive fragment;
process failure, stale review, invalid input or timeout is an error, not UNKNOWN.

The pinned adapter accepts at most 128 facts and rules. Five fixed rules leave
at most 123 reviewed assertions in one native query; larger approved selections
are refused rather than silently truncated. Independently approved numbered
partitions can be combined through /taxonomy-union. For more than 123 reviewed
assertions the host selects a bounded candidate slice, which is then proved by
the same pinned solver; the result reports both counts and the projection.
This does not provide corpus-wide aggregation, and UNKNOWN applies only to the
submitted slice. The process has no OS memory or network isolation. The first
proof is returned, not all possible supports.
The separate /taxonomy-plan remains the bounded Kotlin planner and is not
evidence of native execution.
